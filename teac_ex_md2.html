在現今依賴龐大函式庫與複雜框架的開發環境下，我們往往忽略了「演算法本身」的純粹力量。本文介紹一套由純數學邏輯構建的自定義雜湊（Hash）演算法，其設計初衷是為了在極端受限與多樣化的環境中，提供一致且具備基礎防護的校驗機制。

這段程式碼不僅僅是一個雜湊函數，它是一個針對**「高移植性」與「反向工程防護」**的最佳化解決方案，具備以下無法忽視的核心優勢：

  1. 時光機級的相容性 (JS 1.0 Ready)： 摒棄所有現代語法糖，完全相容於 JavaScript 1.0 標準。這意味著從 1995 年的 Netscape Navigator 2.0、早期的 IE，到最新的 Chrome、Node.js，甚至是資源受限的嵌入式晶片（Embedded Systems），這段程式碼都能原封不動地完美運行。
  2. 天然抗彩虹表 (Rainbow Table Resistance)： 有別於 MD5 或 SHA 系列等公開演算法，本算法採用自定義線性同餘生成器 (LCG) 結合私有混淆字串 (Salt/Pepper)。這使得駭客無法利用網路上現存數 TB 級的「彩虹表」進行秒殺破解，迫使攻擊者必須針對此演算法重新投入高昂的運算成本。
  3. 跨語言的絕對一致性 (Cross-Language Consistency)： 內建手刻的 UTF-8 編碼邏輯，不依賴瀏覽器或作業系統的 API。這解決了長期以來「中文/多位元組字元」在不同程式語言（如 C, Java, Python）與不同平台間 Hash 結果不一致的痛點。無論環境如何改變，只要輸入相同的內容，它永遠吐出唯一的結果。

這是一個為了「寫一次，到處運行 (Write Once, Run Anywhere)」而生的演算法，展現了在最精簡的代碼行數中，如何同時兼顧歷史包袱與現代需求的精妙平衡。

設計目標：

打破時空限制的通用雜湊方案，在設計 ex_md2 演算法與 es1_safe_encodeURI 核心時，我們並非意圖重新發明輪子，而是為了填補現代標準庫與極限環境之間的巨大鴻溝。本演算法的設計哲學圍繞著三個核心指標：極致相容性、跨語言確定性以及針對性的安全防禦。

以下是本演算法旨在達成的四大核心優勢：

1. 穿越時空的相容性 (Time-Travel Compatibility)

現代的加密庫往往依賴龐大的 Polyfill 或最新的 Runtime 環境（如 Node.js 版本、瀏覽器 ES6 支援）。

JS 1.0 原生支援：本程式碼完全摒棄 RegExp、Array.map、encodeURIComponent 等現代語法糖，僅使用最基礎的變數宣告與迴圈邏輯。

應用場景：這意味著它不僅能在最新的 Chrome 上運行，也能在 IE 3.0、Netscape Navigator，甚至是資源極度受限、無標準庫支援的嵌入式 JavaScript 引擎 (IoT/ESP32/微控制器) 中完美運作，無需任何修改。

2. 100% 確定的跨語言一致性 (Cross-Platform Determinism)

許多雜湊演算法在移植時會遇到「字串編碼不一致」的噩夢（例如 Java 的 UTF-16 與 Go 的 UTF-8 處理差異）。

手刻 UTF-8 編碼器：透過內建 es1_safe_encodeURI 函式，我們不依賴瀏覽器的編碼實作，而是直接在位元層級 (Bitwise level) 處理 ASCII 與 Multi-byte 字元。

優勢：這保證了無論輸入是「中文」、「Emoji」還是「特殊符號」，在 JavaScript、C、Python 或 Java 中運算出來的 Hash 結果將是位元級別完全一致的。這對於前後端校驗、跨系統指紋識別至關重要。

3. 抗現有彩虹表攻擊 (Resistance to Rainbow Tables)

傳統的 MD5 或 SHA-1 雖然經典，但網路上已存在數百 GB 的「彩虹表」 (Rainbow Tables)，攻擊者能在毫秒級內反查出原始資料。

自定義演算法邏輯：ex_md2 採用了自定義的線性同餘生成器 (LCG) 參數與混合邏輯，這意味著市面上沒有任何現成的彩虹表可以對應此演算法。

強制性 Pepper/Salt：演算法內部硬編碼了特殊的字符集 (b) 作為運算的一環。攻擊者若不知道這段原始碼中的特定字串，即便擁有強大的算力也無法利用通用的破解工具進行批量還原。

4. 零依賴與輕量化 (Zero Dependency)

在許多專案中，為了引入一個簡單的 Hash 功能而安裝數 MB 的 crypto-js 或其他函式庫是極大的資源浪費。

純數學運算：本演算法僅依賴基礎數學與陣列操作，體積極小，且易於被編譯器優化。

易於移植：由於邏輯單純（無複雜物件導向或閉包），它可以被輕鬆「翻譯」成 C 語言、Assembly 甚至是 SQL Stored Procedure，成為系統間通用的「通用語言」。

混淆效果特性：

以數學混沌對抗暴力破解， 本演算法的核心設計哲學，在於跳脫傳統加密雜湊（如 MD5、SHA 系列）的固定框架，轉而利用基礎數學的混沌特性來構建防禦。這不僅是為了相容性，更是在安全混淆層面上構建了獨特的優勢：

1. 對現有彩虹表（Rainbow Table）的完全免疫

市面上流傳的數百 GB 彩虹表，皆是針對公開標準演算法（MD5, SHA-1, SHA-256）預先計算的結果。本演算法採用自定義邏輯 (Custom Implementation)，這意味著攻擊者手中的任何現成資料庫在面對此演算法產生的字串時，將完全失效。攻擊者若想破解，唯一的途徑是針對此特定演算法重新耗費龐大算力建立查詢表，這極大提升了攻擊成本。

2. 強制性隱式加鹽 (Implicit "Pepper" & Salt)

演算法內部硬編碼了一組非標準的字元集 b（即代碼中的 "rt478..."）。這不僅作為輸出的映射字典，更在運算初期直接參與了雜湊的混合過程。

雙重防護：這個字串同時扮演了 Salt（鹽） 與 Pepper（胡椒） 的角色。即使演算法邏輯被公開，只要這個 b 變數被隱藏或在不同專案中替換，生成的 Hash 結果就會天差地遠，徹底斷絕了跨專案撞庫的可能性。

3. 基於 LCG 的高強度雪崩效應 (Avalanche Effect)

代碼核心運用了線性同餘方法 (LCG) 的數學原理，選用了 MinStd 標準的大質數參數（16807, 48271, 模數 2147483629）。

狀態攪拌：透過 4 個內部狀態暫存器 (s[0]~s[3]) 的交互運算與回饋機制，輸入字串的每一個位元組都會引發內部狀態的劇烈震盪。

結果：哪怕輸入字串只改變了一個 bit（例如 "user1" 變為 "user2"），最終輸出的 30 字元長度雜湊值將會發生翻天覆地的變化，使攻擊者無法透過觀察輸出的相似性來推導輸入內容。

4. 跨時代的位元級一致性 (Bitwise Consistency)

為了對抗不同語言、不同時代瀏覽器對字串編碼的歧義，本演算法內建了手動實作的 UTF-8 編碼器 (es1_safe_encodeURI)。

這確保了無論是在 1998 年的 Netscape、現代的 Chrome，還是 Python/C++ 的後端環境中，對「中文」或特殊符號的二進位解析都是絕對精確且一致的。這消除了因編碼庫差異導致的混淆失敗，確保了演算法在任何極端環境下的穩定性與可移植性。

<?php
define('EX_MD2_CHARS', "rt478aGHLTdbADEFyu3MeRfhi6mnQj"); // 30 chars
define('EX_MD2_M', 2147483629.0); // Prime < 2^31, 儲存為 float

function ex_md2($str) {
    
    // 從常數獲取值
    $chars = EX_MD2_CHARS;
    
    /** @var float $M (從 define() 獲取，已確保為 float) */
    $M = EX_MD2_M; 
    
    /** @var float $s1 */
    $s1 = 19850721.0;
    /** @var float $s2 */
    $s2 = 98765432.0;
    /** @var float $s3 */
    $s3 = 12345678.0;
    /** @var float $s4 */
    $s4 = 55119733.0;
    
    $str = rawurlencode($str) . "rt478aGHLTdbADEFyu3MeRfhi6mnQj";
    
    /** @var int $len */
    $len = strlen($str);

    // 3. 處理迴圈 (Processing Loop)
    for ($i = 0; $i < $len; $i++) {
        
        $c = ord($str[$i]);
        
        // 混合運算 (Mixing Round)
        
        $s1 = fmod(($s1 * 16807.0 + $c), $M);
        $s2 = fmod(($s2 * 48271.0 + $s1), $M);
        
        $tempS3 = (int)$s3 ^ (int)$s1;
        
        if ($tempS3 < 0) {
            $tempS3 += 2147483648.0;
        }
        
        // $tempS3 此刻可能是 int 或 float，但 fmod() 均可處理
        $s3 = fmod($tempS3, $M);
        
        $s4 = fmod(($s4 + $s2 + $c * 13.0), $M);
    }

    /** @var string $res */
    $res = "";
    
    // 4. 產出迴圈 (Output Loop)
    for ($i = 0; $i < 41; $i++) {
        // 狀態變更 (State Mutation)
        $s1 = fmod(($s1 * 16807.0), $M);
        $s2 = fmod(($s2 * 37.0 + $s1), $M);
        $s3 = fmod(($s3 + $s4 + $i), $M); // $i (int) 被提升為 float
        $s4 = fmod(($s4 * 48271.0), $M);
        
        $idx_f = fmod(($s1 + $s2 + $s3 + $s4), 30.0);
        
        /** @var int $idx */
        $idx = (int)$idx_f;
        
        if ($idx < 0) {
            $idx += 30;
        }
        
        $res .= $chars[$idx];
    }
    
    return $res;
}

// 加密 n 次
function ex_md2n($a, $n) {
    for ($i = 0; $i < $n; $i++) {
        $a = ex_md2($a);
    }
    return $a;
}

function es1_safe_encodeURI(str) {
    var output = "";
    var hexChars = "0123456789ABCDEF";

    var safeChars = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_.!~*'();,/?@&=+$#";

    function percentEncode(byteVal) {
        var high = (byteVal >> 4) & 0x0F; // 取得高 4-bit
        var low = byteVal & 0x0F;       // 取得低 4-bit
        return "%" + hexChars.charAt(high) + hexChars.charAt(low);
    }

    for (var i = 0; i < str.length; i++) {
        var c_code = str.charCodeAt(i);
        var c_char = str.charAt(i);

        // 檢查是否為安全字元
        var isSafe = false;
        for (var j = 0; j < safeChars.length; j++) {
            if (safeChars.charAt(j) == c_char) {
                isSafe = true;
                break;
            }
        }

        if (isSafe) {
            output += c_char;
        } else {
            if (c_code >= 0 && c_code <= 127) {
                output += percentEncode(c_code);
            } 
            else if (c_code >= 128 && c_code <= 2047) {
                var byte1 = 192 | (c_code >> 6);         // 110xxxxx
                var byte2 = 128 | (c_code & 63);       // 10xxxxxx
                output += percentEncode(byte1) + percentEncode(byte2);
            }

                var byte2 = 128 | ((c_code >> 6) & 63);  // 10xxxxxx
                var byte3 = 128 | (c_code & 63);       // 10xxxxxx
                output += percentEncode(byte1) + percentEncode(byte2) + percentEncode(byte3);
            }
        }
    }
    return output;
}

import urllib.parse

def ex_md2(a: str) -> str:
    """
    包含了對 encodeURI、整數溢位處理、Bitwise 特性與 Modulo 運算的精確對應。
    """
    
    # 1. 定義常數
    b = "rt478aGHLTdbADEFyu3MeRfhi6mnQj"
    M = 2147483629  # 這是一個質數，且小於 2^31 - 1 (Int32 Max)
    s = [19850721, 98765432, 12345678, 55119733]

    # 2. 處理 encodeURI (關鍵差異點)
    # A-Z a-z 0-9 ; , / ? : @ & = + $ - _ . ! ~ * ' ( ) #
    # Python 的 urllib.parse.quote 預設會編碼很多符號，必須透過 safe 參數指定保留字元以完全模擬 JS 行為。
    js_safe_chars = ";,/?:@&=+$-_.!~*'()#" 
    a_encoded = urllib.parse.quote(a, safe=js_safe_chars)

    # 拼接字串 (此時已全為 ASCII 字符)
    processed_str = a_encoded + b

    # 3. 第一階段迴圈：混合狀態
    for char in processed_str:
        c = ord(char) # 由於經過 encodeURI，這裡保證是 ASCII (0-127)
        
        s[0] = (s[0] * 16807 + c) % M
        s[1] = (s[1] * 48271 + s[0]) % M
        
        # 關於 XOR (^):
        # JS 的 Bitwise 會將數字轉為 32-bit Signed Integer。
        # 這裡的數值都在 M (約21億) 以內，且為正數，沒有超過 31 bit。
        # 因此 Python 的無限精度整數 XOR 行為與 JS 在此範圍內完全一致。
        s[2] = (s[2] ^ s[0]) % M
        
        # 關於負數修正:
        # JS 的 % 運算符如果是負數被除，結果會是負數 (例如 -5 % 30 = -5)。
        # Python 的 % 運算符結果永遠是正數 (例如 -5 % 30 = 25)。
        # 雖然此處 s[2] 理論上因輸入為正且 M < 2^31 不會產生負數，但為了嚴謹性，
        # 我們保留邏輯：在 Python 中， % M 自動處理了 JS 需要 `if < 0 then += M` 的情況。
        # 但若要與原始碼邏輯結構完全映射，Python 的 % 已經保證了結果在 [0, M-1]。
        
        s[3] = (s[3] + s[1] + c * 13) % M

    # 4. 第二階段迴圈：生成結果
    res = []
    for i in range(41):
        s[0] = (s[0] * 16807) % M
        s[1] = (s[1] * 37 + s[0]) % M
        s[2] = (s[2] + s[3] + i) % M
        s[3] = (s[3] * 48271) % M
        
        # 計算索引
        # JS 原碼：var idx = (sum) % 30; if (idx < 0) idx += 30;
        # JS 的 % 可能算出負數，所以它需要 if (idx < 0) idx += 30 來轉正。
        # Python 的 % 運算符 (sum % 30) 自動會將結果映射到 [0, 29] 區間。
        # 例子：JS (-1 % 30 = -1 -> +30 = 29) 等同於 Python (-1 % 30 = 29)。
        # 因此直接使用 Python 的 % 30 即可完美包含 JS 的修正邏輯。
        idx = (s[0] + s[1] + s[2] + s[3]) % 30
        
        res.append(b[idx])

    return "".join(res)

string urlEncode(const string& value) {
    ostringstream escaped;
    escaped.fill('0');
    escaped << hex << uppercase;

    for (char c_char : value) {
        // 將 char 提升為 unsigned char 處理，以避免符號擴充問題 (特別是對於負的 char/byte)
        unsigned char c = (unsigned char)c_char; 
        
        // 判斷是否需要編碼 (encodeURI 的基本原則：對所有非 ASCII 字符和部分保留字符進行編碼)
        // 這裡採用一個近似且安全的策略：僅保留 RFC 3986 的 unreserved characters (a-zA-Z0-9-._~)
        // 加上 encodeURI 特意保留的 URI reserved characters (;/?:@&=+$,#)
        if (isalnum(c) || c == '-' || c == '_' || c == '.' || c == '~' || 
            c == ';' || c == '/' || c == '?' || c == ':' || c == '@' || 
            c == '&' || c == '=' || c == '+' || c == '$' || c == ',' || c == '#') {
            escaped << c_char;
        } else if (c_char == ' ') {
            // encodeURI 將空格編碼為 %20 (而非 application/x-www-form-urlencoded 的 '+')
            escaped << "%20";
        } else {
            // 其他字符 (包括所有非 ASCII 的多位元組 UTF-8 序列的位元組) 都進行百分號編碼
            escaped << '%' << setw(2) << (int)c;
        }
    }
    return escaped.str();
}

        // 使用 long 以防止 (s[x] * 16807) 等運算產生 int 溢位
        String b = "rt478aGHLTdbADEFyu3MeRfhi6mnQj";
        long M = 2147483629L; 
        long[] s = {19850721L, 98765432L, 12345678L, 55119733L};

        // 2. 預處理字串：模擬 JS 的 encodeURI(a) + b
        // Java 的 URLEncoder.encode 預設會將空格轉為 "+" (Form 格式)，
        // 但 JS 的 encodeURI 會轉為 "%20"。必須替換以確保雜湊結果一致。
        String encodedA = "";
        try {
            encodedA = URLEncoder.encode(a, StandardCharsets.UTF_8.toString())
                        .replace("+", "%20")
                        .replace("%7E", "~")  // JS encodeURI 不編碼 '~'
                        .replace("%27", "'")  // JS encodeURI 不編碼單引號
                        .replace("%28", "(")  // JS encodeURI 不編碼括號
                        .replace("%29", ")");
            
            // 注意：若您的輸入包含 URL 特殊字元（如 / ? : @ & =），JS encodeURI 會保留它們，
            // 但 URLEncoder 會轉碼。若輸入僅為一般字串ID，上述修正已足夠。
            // 若需嚴格 100% 符合含有 URL 符號的輸入，需更複雜的實作，但通常此邏輯用於一般字串。
            
        } catch (UnsupportedEncodingException e) {
            e.printStackTrace(); // UTF-8 應該永遠支援，這裡僅為防禦性編碼
            return ""; 
        }
        
        String input = encodedA + b;

        // 3. 第一階段混淆 (Loop 1)
        for (int i = 0; i < input.length(); i++) {
            long c = (long) input.charAt(i); // 取得字元碼 (Unicode code unit)

            s[0] = (s[0] * 16807 + c) % M;
            s[1] = (s[1] * 48271 + s[0]) % M;

            // JS 的 Bitwise XOR 會將數值視為 32-bit int。
            // 因為 M < 2^31，s[] 數值皆在正整數 31-bit 範圍內，
            // 直接用 Java 的 long 進行 XOR 運算結果與 JS 一致。
            s[2] = (s[2] ^ s[0]) % M;

            // 修正負數模運算 (雖然 XOR 且 M 為正數通常結果為正，但保留原邏輯防禦)
            if (s[2] < 0) s[2] += M;

            s[3] = (s[3] + s[1] + c * 13) % M;
        }

        // 4. 第二階段生成結果 (Loop 2)
        StringBuilder res = new StringBuilder();
        for (int i = 0; i < 41; i++) {
            s[0] = (s[0] * 16807) % M;
            s[1] = (s[1] * 37 + s[0]) % M;
            s[2] = (s[2] + s[3] + i) % M;
            s[3] = (s[3] * 48271) % M;

            long sum = s[0] + s[1] + s[2] + s[3];
            long idx = sum % 30;

            // Java 的 % 對負數運算會保留負號 (例如 -5 % 3 = -2)，需修正為正索引
            if (idx < 0) idx += 30;

            res.append(b.charAt((int) idx));
        }

        return res.toString();
    }

// ExMD2 
// 輸入: a string
// 輸出: 加密/混淆後的字串
func ExMD2(a string) string {
	// 1. 定義常數與參數
	const b = "rt478aGHLTdbADEFyu3MeRfhi6mnQj"
	// 使用 int64 避免運算過程中的整數溢位 (48271 * 2147483629 超過 int32)
	const M int64 = 2147483629
	
	// 初始化狀態陣列，明確使用 int64
	s := [4]int64{19850721, 98765432, 12345678, 55119733}

	// 2. 處理 encodeURI 與 Salt
	// Go: url.PathEscape 最接近 JS 的 encodeURI 行為
	// 注意：encodeURI 後的字串只包含 ASCII 字符
	encodedA := url.PathEscape(a)
	combined := encodedA + b

	// 3. 第一階段混淆 (Loop 1)
	// 將字串轉為 byte slice 進行遍歷，這等同於 JS 對 ASCII 字串做 charCodeAt
	inputBytes := []byte(combined)

	for _, byteVal := range inputBytes {
		c := int64(byteVal)

		s[0] = (s[0]*16807 + c) % M
		s[1] = (s[1]*48271 + s[0]) % M

		// XOR 運算
		// 在 JS 中，Bitwise 會強制轉為 32bit int。
		// 由於 M < 2^31，且 s[] 皆為正數，int64 直接 XOR 的結果與 JS 邏輯一致。
		s[2] = (s[2] ^ s[0]) % M

		// 防禦性修正：確保取餘數後不為負 (雖然理論上 XOR 正數仍為正，但保留原邏輯)
		if s[2] < 0 {
			s[2] += M
		}

		s[3] = (s[3] + s[1] + c*13) % M
	}

	// 4. 第二階段混淆與輸出 (Loop 2)
	var res strings.Builder
	// 預先分配記憶體以提升效能 (41 個字符)
	res.Grow(41)

	for i := 0; i < 41; i++ {
		s[0] = (s[0] * 16807) % M
		s[1] = (s[1] * 37 + s[0]) % M
		// 注意這裡的 i 需要轉為 int64 才能與 s[2] 相加
		s[2] = (s[2] + s[3] + int64(i)) % M
		s[3] = (s[3] * 48271) % M

		// 計算索引
		sum := s[0] + s[1] + s[2] + s[3]
		idx := sum % 30

		// 修正 Go 語言中負數取模的特性 (類似 JS，-5 % 30 = -5)
		if idx < 0 {
			idx += 30
		}

		// 從 b 字串取字元並加入結果
		// idx 是 int64，需轉回 int 作為索引
		res.WriteByte(b[int(idx)])
	}

	return res.String()
}

// Configuration

#define OUTPUT_LEN 41
#define SALT_LEN 30
// 為了確保每個 Thread 都能處理不同長度的字串，我們假設最大長度。
// 實際應用中，建議使用扁平化陣列 (Flat Array) + 偏移量 (Offset) 來處理變長輸入。
#define MAX_INPUT_LEN 256 

// ==========================================
// Device Constant Memory (Charset / Salt)
// ==========================================
// 將 b 放在常數記憶體中以加速讀取
__constant__ char d_b[SALT_LEN + 1] = "rt478aGHLTdbADEFyu3MeRfhi6mnQj";

// ==========================================
// CUDA Kernel: ex_md2
// ==========================================
__global__ void ex_md2_kernel(const char* inputs, const int* input_lens, char* outputs, int num_items) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    
    if (idx >= num_items) return;

    // 1. 取得當前 Thread 對應的輸入字串位置
    // 注意：這裡假設 inputs 是一個扁平化的 2D 陣列 [num_items][MAX_INPUT_LEN]
    // 如果使用 char** 需要 Deep Copy，這裡為了穩定性使用固定跨度 (Stride)
    const char* my_input = inputs + (idx * MAX_INPUT_LEN);
    char* my_output = outputs + (idx * (OUTPUT_LEN + 1)); // +1 for null terminator
    int a_len = input_lens[idx];

    // 2. 初始化變數
    // 必須使用 int64_t (long long) 避免乘法溢位
    // JS 的 M = 2147483629 (小於 2^31，但乘法運算會超)
    const int64_t M = 2147483629; 
    
    // 狀態陣列 s
    int64_t s[4] = {19850721, 98765432, 12345678, 55119733};

    // 3. 邏輯第一階段：遍歷 a + b
    // 我們不真的拼接字串，而是用虛擬索引
    int total_len = a_len + SALT_LEN;

    for (int i = 0; i < total_len; i++) {
        int64_t c;
        
        // 虛擬拼接邏輯
        if (i < a_len) {
            c = (int64_t)(unsigned char)my_input[i]; // 確保轉為正整數 ASCII
        } else {
            c = (int64_t)(unsigned char)d_b[i - a_len];
        }

        // 數學運算 (嚴格對照 JS 邏輯)
        // s[0] = (s[0] * 16807 + c) % M;
        s[0] = (s[0] * 16807 + c) % M;

        // s[1] = (s[1] * 48271 + s[0]) % M;
        s[1] = (s[1] * 48271 + s[0]) % M;

        // s[2] = (s[2] ^ s[0]) % M;
        // 注意：JS 的 Bitwise XOR 會將數值轉為 32-bit Signed Int。
        // 雖然這裡 s 的值都在 M 範圍內且 M < 2^31，但為了嚴謹，我們先轉 int 再做 XOR
        // 因為 s[] 始終是正數且小於 M (21億)，強制轉型安全。
        int32_t s2_32 = (int32_t)s[2];
        int32_t s0_32 = (int32_t)s[0];
        int64_t xor_res = (int64_t)(s2_32 ^ s0_32);
        
        s[2] = xor_res % M;

        // 修正負數模運算 (JS: if(s[2] < 0) s[2] += M)
        // 雖然 XOR 兩個正數通常是正數，但若最高位被設為 1 且被視為 signed，C 的 % 可能會給出負數
        if (s[2] < 0) s[2] += M;

        // s[3] = (s[3] + s[1] + c * 13) % M;
        s[3] = (s[3] + s[1] + c * 13) % M;
    }

    // 4. 邏輯第二階段：生成結果 (41 次迭代)
    for (int i = 0; i < OUTPUT_LEN; i++) {
        s[0] = (s[0] * 16807) % M;
        s[1] = (s[1] * 37 + s[0]) % M;
        s[2] = (s[2] + s[3] + i) % M;
        s[3] = (s[3] * 48271) % M;

        // var idx = (s[0] + s[1] + s[2] + s[3]) % 30;
        int64_t sum_s = s[0] + s[1] + s[2] + s[3];
        int char_idx = (int)(sum_s % 30);

        // if (idx < 0) idx += 30;
        if (char_idx < 0) char_idx += 30;

        // res += b.charAt(idx);
        my_output[i] = d_b[char_idx];
    }

    // 添加字串結束符
    my_output[OUTPUT_LEN] = '\0';
}

CREATE PROCEDURE ex_md2_proc(

    DECLARE v_s0 BIGINT DEFAULT 19850721;
    DECLARE v_s1 BIGINT DEFAULT 98765432;
    DECLARE v_s2 BIGINT DEFAULT 12345678;
    DECLARE v_s3 BIGINT DEFAULT 55119733;

    DECLARE v_str_len INT;

    DECLARE v_c INT;  -- 存放 charCodeAt
    DECLARE v_j INT;
    DECLARE v_idx BIGINT;

    -- 注意：這裡假設 p_input_str 已經是 encodeURI 後的結果，或者僅包含 ASCII
    SET v_combined_str = CONCAT(p_input_str, v_b);
    SET v_str_len = CHAR_LENGTH(v_combined_str);
    
    -- 3. 第一階段迴圈：混合輸入字串 (Scramble based on input)
    SET v_i = 1; -- MySQL 字串從 1 開始
    WHILE v_i <= v_str_len DO
        -- 取得字元 ASCII/Unicode 碼 (對應 JS: a.charCodeAt(i))
        -- ORD() 對於多字節字符能返回正確數值，比 ASCII() 安全
        SET v_c = ORD(SUBSTRING(v_combined_str, v_i, 1));
        
        -- s[0] = (s[0] * 16807 + c) % M;
        SET v_s0 = (v_s0 * 16807 + v_c) % v_M;
        
        -- s[1] = (s[1] * 48271 + s[0]) % M;
        SET v_s1 = (v_s1 * 48271 + v_s0) % v_M;
        
        -- s[2] = (s[2] ^ s[0]) % M;
        -- MySQL ^ 運算符與 JS Bitwise XOR 行為在正整數範圍內一致
        SET v_s2 = (v_s2 ^ v_s0) % v_M;
        
        -- 修正負數 (JS: if(s[2] < 0) s[2] += M;)
        IF v_s2 < 0 THEN
            SET v_s2 = v_s2 + v_M;
        END IF;
        
        -- s[3] = (s[3] + s[1] + c * 13) % M;
        SET v_s3 = (v_s3 + v_s1 + v_c * 13) % v_M;
        
        SET v_i = v_i + 1;
    END WHILE;

    -- 4. 第二階段迴圈：生成結果字串 (Generate Result)
    -- JS: for (var i = 0; i < 41; i++)
    SET v_j = 0;
    WHILE v_j < 41 DO
        -- s[0] = (s[0] * 16807) % M;
        SET v_s0 = (v_s0 * 16807) % v_M;
        
        -- s[1] = (s[1] * 37 + s[0]) % M;
        SET v_s1 = (v_s1 * 37 + v_s0) % v_M;

        -- s[3] = (s[3] * 48271) % M;

        SET v_j = v_j + 1;
    END WHILE;

    -- 5. 輸出結果
    SET p_result = v_res;

END //

; ----------------------------------------------------------------------------------------
; 檔案名稱: ex_md2.asm
; 編譯方式 (Linux):
;   nasm -f elf64 ex_md2.asm -o ex_md2.o
;   gcc main.c ex_md2.o -o ex_md2_program
;
; 函式原型:
;   void ex_md2_asm(const char* input, char* output);
;
; 參數暫存器 (System V AMD64 ABI):
;   RDI: 指向輸入字串 (input) 的指標
;   RSI: 指向輸出緩衝區 (output) 的指標 (Caller 需確保至少 42 bytes: 41 chars + null)
; ----------------------------------------------------------------------------------------

section .data
    ; 預定義常數與 charset
    charset db "rt478aGHLTdbADEFyu3MeRfhi6mnQj", 0
    CHARSET_LEN equ 30
    
    ; 模數 M = 2147483629
    MOD_M equ 2147483629
    
    ; 初始狀態 s = [19850721, 98765432, 12345678, 55119733]
    init_s dd 19850721, 98765432, 12345678, 55119733

section .text
    global ex_md2_asm

ex_md2_asm:
    ; 保存 Callee-saved registers (根據 ABI 規範，RBX, R12-R15 需保存)
    push rbx
    push r12
    push r13
    push r14
    push r15

    ; --- 初始化變數 ---
    ; 我們使用暫存器來模擬 s[0]...s[3] 以達到最高速度
    ; R8D  = s[0]
    ; R9D  = s[1]
    ; R10D = s[2]
    ; R11D = s[3]
    ; R12  = MOD_M (用於除法)
    
    mov r8d,  [rel init_s]      ; s[0]
    mov r9d,  [rel init_s + 4]  ; s[1]
    mov r10d, [rel init_s + 8]  ; s[2]
    mov r11d, [rel init_s + 12] ; s[3]
    
    mov r12, MOD_M              ; M
    
    ; --- 階段 1: 處理輸入字串 a (虛擬串接的第一部分) ---
    ; 指標: RDI (input string)
    
.process_input_loop:
    movzx ecx, byte [rdi]       ; 讀取一個 byte 到 ECX (變數 c)
    test ecx, ecx               ; 檢查是否為 Null terminator (0)
    jz .process_charset_start   ; 如果字串結束，跳轉到處理 charset
    
    call .mix_step              ; 呼叫混合邏輯 (Mix Step)
    
    inc rdi                     ; 移動到下一個字元
    jmp .process_input_loop

    ; --- 階段 2: 處理 Charset b (虛擬串接的第二部分) ---
    ; 這對應 JS 中的 a = a + b; 迴圈繼續跑 b 的部分
    
.process_charset_start:
    lea r13, [rel charset]      ; 取得 charset 地址
    xor r14, r14                ; 迴圈計數器 i = 0

.process_charset_loop:
    cmp r14, CHARSET_LEN        ; 檢查是否跑完 30 個字元
    je .generate_output_start   ; 跑完則進入輸出產生階段
    
    movzx ecx, byte [r13 + r14] ; c = charset[i]
    
    call .mix_step              ; 呼叫混合邏輯
    
    inc r14
    jmp .process_charset_loop

    ; --- 核心混合邏輯 (Inline Function) ---
    ; 輸入: ECX (c), R8D..R11D (s[0]..s[3]), R12 (M)
    ; 輸出: 更新後的 R8D..R11D
.mix_step:
    ; 1. s[0] = (s[0] * 16807 + c) % M
    mov eax, r8d
    imul rax, 16807             ; 64-bit 乘法，防止溢位
    add rax, rcx                ; + c
    xor edx, edx                ; 清空 RDX 準備除法
    div r12                     ; div M, 結果: RAX=商, RDX=餘數
    mov r8d, edx                ; 更新 s[0]

    ; 2. s[1] = (s[1] * 48271 + s[0]) % M
    mov eax, r9d
    imul rax, 48271
    add rax, r8                 ; + s[0] (此時 r8d 已經是更新過的值)
    xor edx, edx
    div r12
    mov r9d, edx                ; 更新 s[1]

    ; 3. s[2] = (s[2] ^ s[0]) % M
    ; JS 的 XOR 是 32-bit signed，但因為我們的值都在 0 ~ M-1 (小於 2^31)，
    ; 符號位元永遠是 0，所以直接 XOR 即可，無需擔心負數處理。
    xor r10d, r8d               ; s[2] ^ s[0]
    mov eax, r10d
    xor edx, edx
    div r12
    mov r10d, edx               ; 更新 s[2]

    ; JS 程式碼中有一句: if(s[2] < 0) s[2] += M;
    ; 由於我們的輸入都是正整數且小於 2^31，XOR 後不可能產生負數 (MSB 為 0)。
    ; 且 DIV 指令是 Unsigned Division，餘數恆正。此檢查在 ASM 中為冗餘，已安全省略。

    ; 4. s[3] = (s[3] + s[1] + c * 13) % M
    mov eax, ecx
    imul eax, 13                ; c * 13
    add eax, r11d               ; + s[3]
    add eax, r9d                ; + s[1]
    ; 注意：三次加法可能溢位 32-bit，所以我們用 64-bit RAX 運算 (eax 進位會到 rax 高位)
    ; 但為了嚴謹，我們先將運算元轉為 64-bit 再加
    mov rax, rcx
    imul rax, 13
    mov rbx, r11
    add rax, rbx
    mov rbx, r9
    add rax, rbx                ; 現在 rax 包含了總和
    xor edx, edx
    div r12
    mov r11d, edx               ; 更新 s[3]
    
    ret

    ; --- 階段 3: 生成結果字串 (Generate Loop) ---
    ; 迴圈 41 次
    
.generate_output_start:
    xor r14, r14                ; loop counter i = 0

.gen_loop:
    cmp r14, 41
    je .done
    
    ; 1. s[0] = (s[0] * 16807) % M
    mov eax, r8d
    imul rax, 16807
    xor edx, edx
    div r12
    mov r8d, edx

    ; 2. s[1] = (s[1] * 37 + s[0]) % M
    mov eax, r9d
    imul rax, 37
    add rax, r8
    xor edx, edx
    div r12
    mov r9d, edx

    ; 3. s[2] = (s[2] + s[3] + i) % M
    mov rax, r10                ; s[2]
    add rax, r11                ; + s[3]
    add rax, r14                ; + i
    xor edx, edx
    div r12
    mov r10d, edx

    ; 4. s[3] = (s[3] * 48271) % M
    mov eax, r11d
    imul rax, 48271
    xor edx, edx
    div r12
    mov r11d, edx

    ; --- 計算 idx ---
    ; var idx = (s[0] + s[1] + s[2] + s[3]) % 30;
    mov rax, r8
    add rax, r9
    add rax, r10
    add rax, r11
    
    mov rcx, 30                 ; Divisor 30
    xor edx, edx
    div rcx                     ; RDX = Remainder (idx)
    
    ; JS: if (idx < 0) idx += 30;
    ; ASM DIV is unsigned, remainder is always positive [0, 29].
    ; No correction needed.
    
    ; --- 查表並寫入結果 ---
    ; res += b.charAt(idx);
    lea rbx, [rel charset]
    mov al, byte [rbx + rdx]    ; Load char from charset at idx
    mov byte [rsi + r14], al    ; Store to output buffer at pos i
    
    inc r14
    jmp .gen_loop

.done:
    ; Null terminate output string
    mov byte [rsi + 41], 0
    
    ; 恢復暫存器
    pop r15
    pop r14
    pop r13
    pop r12
    pop rbx
    
    ret

' ==========================================
' 主函數: ex_md2_VBA

' ==========================================
Public Function ex_md2_VBA(ByVal a As String) As String
    Dim b As String
    Dim M As Double ' 使用 Double 防止乘法溢位 (Long 上限僅 21億)
    Dim s(0 To 3) As Double
    Dim i As Long
    Dim c As Long
    Dim encodedA As String
    Dim res As String
    Dim idx As Long
    
    ' 1. 初始化常數與狀態向量
    b = "rt478aGHLTdbADEFyu3MeRfhi6mnQj"
    M = 2147483629# ' # 強制視為 Double
    
    s(0) = 19850721
    s(1) = 98765432
    s(2) = 12345678
    s(3) = 55119733
    
    ' 2. 預處理: encodeURI(a) + b
    ' 注意: 必須使用符合 JS encodeURI 行為的函數
    encodedA = JSEncodeURI(a) & b
    
    ' 3. 第一階段迴圈: 混淆狀態向量
    Dim tempVal As Double
    Dim xorVal As Long
    
    For i = 1 To Len(encodedA)
        ' 取得字元 ASCII/Unicode Code (因為已 Encode，此處皆為 ASCII)
        c = Asc(Mid(encodedA, i, 1))
        
        ' s[0] = (s[0] * 16807 + c) % M
        ' 拆解運算以確保 Double 精度
        tempVal = (s(0) * 16807#) + c
        s(0) = RawMod(tempVal, M)
        
        ' s[1] = (s[1] * 48271 + s[0]) % M
        tempVal = (s(1) * 48271#) + s(0)
        s(1) = RawMod(tempVal, M)
        
        ' s[2] = (s[2] ^ s[0]) % M
        ' JS 的 Bitwise 操作是基於 32bit Int。
        ' M 小於 2147483647，所以 s(n) 轉 Long 是安全的。
        xorVal = CLng(s(2)) Xor CLng(s(0))
        s(2) = RawMod(CDbl(xorVal), M)
        
        ' 修正 JS 負數模運算特性 (防禦性編碼，雖然 XOR 通常為正)
        If s(2) < 0 Then s(2) = s(2) + M
        
        ' s[3] = (s[3] + s[1] + c * 13) % M
        tempVal = s(3) + s(1) + (c * 13#)
        s(3) = RawMod(tempVal, M)
    Next i
    
    ' 4. 第二階段迴圈: 產生結果字串 (41 次)
    res = ""
    For i = 0 To 40
        ' s[0] = (s[0] * 16807) % M
        s(0) = RawMod(s(0) * 16807#, M)
        
        ' s[1] = (s[1] * 37 + s[0]) % M
        s(1) = RawMod((s(1) * 37#) + s(0), M)
        
        ' s[2] = (s[2] + s[3] + i) % M
        s(2) = RawMod(s(2) + s(3) + i, M)
        
        ' s[3] = (s[3] * 48271) % M
        s(3) = RawMod(s(3) * 48271#, M)
        
        ' var idx = (s[0] + s[1] + s[2] + s[3]) % 30
        tempVal = s(0) + s(1) + s(2) + s(3)
        idx = CLng(RawMod(tempVal, 30))
        
        ' if (idx < 0) idx += 30
        If idx < 0 Then idx = idx + 30
        
        ' res += b.charAt(idx)
        ' VBA Mid 是 1-based，所以要 +1
        res = res & Mid(b, idx + 1, 1)
    Next i
    
    ex_md2_VBA = res
    
End Function

' ==========================================
' 工具函數: RawMod
' 功能: 解決 VBA Mod 運算符在大數(Double)時會溢位的 BUG
' 邏輯: a % b = a - floor(a / b) * b
' ==========================================
Private Function RawMod(ByVal Number As Double, ByVal Divisor As Double) As Double
    RawMod = Number - Fix(Number / Divisor) * Divisor
End Function

' ==========================================
' 工具函數: JSEncodeURI
' 特性:
'   1. 處理 UTF-8 多字節字符 (如中文)
'   2. 保留 encodeURI 的白名單字符不轉碼 (A-Z a-z 0-9 ; , / ? : @ & = + $ - _ . ! ~ * ' ( ) #)
' ==========================================
Private Function JSEncodeURI(ByVal txt As String) As String
    Dim i As Long
    Dim b() As Byte
    Dim utf8Bytes() As Byte
    Dim ret As String
    Dim charCode As Integer
    Dim k As Long
    
    ' 轉換字串為 UTF-8 Bytes
    utf8Bytes = ToUTF8Array(txt)
    
    ret = ""
    For k = LBound(utf8Bytes) To UBound(utf8Bytes)
        charCode = utf8Bytes(k)
        
        ' 判斷是否為 encodeURI 的安全字符 (不需轉碼)
        ' 參考 JS 標準: alnums, -, _, ., !, ~, *, ', (, ), #, ;, ,, /, ?, :, @, &, =, +, $
        ' 這裡使用 ASCII 碼範圍判斷以求高效
        
        Dim isSafe As Boolean
        isSafe = False
        
        Select Case charCode
            Case 48 To 57, 65 To 90, 97 To 122 ' 0-9, A-Z, a-z
                isSafe = True
            Case 45, 95, 46, 33, 126, 42, 39, 40, 41 ' - _ . ! ~ * ' ( )
                isSafe = True
            Case 35, 59, 44, 47, 63, 58, 64, 38, 61, 43, 36 ' # ; , / ? : @ & = + $
                isSafe = True
        End Select
        
        If isSafe Then
            ret = ret & Chr(charCode)
        Else
            ' 轉為 %HEX
            Dim hexStr As String
            hexStr = Hex(charCode)
            If Len(hexStr) = 1 Then hexStr = "0" & hexStr
            ret = ret & "%" & hexStr
        End If
    Next k
    
    JSEncodeURI = ret
End Function

' ==========================================
' 工具函數: ToUTF8Array
' 功能: 將 VBA 內部字串 (UTF-16 LE) 轉為 UTF-8 Byte Array
' 備註: 不依賴 ADODB.Stream，純 API 或邏輯處理以確保相容性
' ==========================================
Private Function ToUTF8Array(ByVal sStr As String) As Byte()
    Dim i As Long
    Dim c As Long
    Dim utf8Arr() As Byte
    Dim pos As Long
    Dim byteLen As Long
    
    ' 預估最大長度 (所有字都是 3 bytes)
    ReDim utf8Arr(0 To Len(sStr) * 3 + 10)
    pos = 0
    
    For i = 1 To Len(sStr)
        c = AscW(Mid(sStr, i, 1))
        If c < 0 Then c = c + 65536 ' 修正 VBA 負數 Unicode 表現
        
        If c < 128 Then
            ' 1 Byte: 0xxxxxxx
            utf8Arr(pos) = c
            pos = pos + 1
        ElseIf c < 2048 Then
            ' 2 Bytes: 110xxxxx 10xxxxxx
            utf8Arr(pos) = 192 + (c \ 64)
            utf8Arr(pos + 1) = 128 + (c And 63)
            pos = pos + 2
        Else
            ' 3 Bytes: 1110xxxx 10xxxxxx 10xxxxxx
            ' BMP 範圍內 (0-FFFF)
            utf8Arr(pos) = 224 + (c \ 4096)
            utf8Arr(pos + 1) = 128 + ((c \ 64) And 63)
            utf8Arr(pos + 2) = 128 + (c And 63)
            pos = pos + 3
        End If
    Next i
    
    ' 縮減陣列大小至實際長度
    If pos > 0 Then
        ReDim Preserve utf8Arr(0 To pos - 1)
    Else
        ReDim utf8Arr(-1 To -1) ' Empty
    End If
    
    ToUTF8Array = utf8Arr
End Function

sub ex_md2 {

    # 1. 參數定義
    my $b_str = "rt478aGHLTdbADEFyu3MeRfhi6mnQj";
    my $M     = 2147483629;
    my @s     = (19850721, 98765432, 12345678, 55119733);

    # JS encodeURI 不編碼的字元集合: A-Z a-z 0-9 ; , / ? : @ & = + $ - _ . ! ~ * ' ( ) #
    # 我們使用 uri_escape_utf8，第二個參數是"要編碼的不安全字元"，
    # 所以我們使用 "反向(轉義除此以外的所有字元)" 的 Regex。
    my $encoded_a = uri_escape_utf8($a, "^A-Za-z0-9\-_.!~*'();,/?:@&=+\$#");

    # 拼接 Salt
    $a = $encoded_a . $b_str;

    # 將字串轉換為 ASCII/UTF8 Byte 數值陣列
    my @chars = map { ord($_) } split(//, $a);
    my $len = scalar(@chars);

    # 3. 核心混淆迴圈 (First Loop)
    for (my $i = 0; $i < $len; $i++) {
        my $c = $chars[$i];

        # s[0] = (s[0] * 16807 + c) % M
        # 注意: 乘法結果可能超過 32bit 整數範圍，使用 float_mod 確保安全
        $s[0] = float_mod($s[0] * 16807 + $c, $M);

        # s[1] = (s[1] * 48271 + s[0]) % M
        $s[1] = float_mod($s[1] * 48271 + $s[0], $M);

        # s[2] = (s[2] ^ s[0]) % M
        # Bitwise XOR 在 Perl 會強制轉整數，由於數值 < M (約21億)，在 32bit 範圍內，安全。
        $s[2] = float_mod(($s[2] ^ $s[0]), $M);

        # JS 負數修正邏輯 (雖然 s[2] 來自 mod M 應為正，但保留邏輯以防萬一)
        if ($s[2] < 0) { $s[2] += $M; }

        # s[3] = (s[3] + s[1] + c * 13) % M
        $s[3] = float_mod($s[3] + $s[1] + $c * 13, $M);
    }

    # 4. 產出結果迴圈 (Second Loop)
    my $res = "";
    for (my $i = 0; $i < 41; $i++) {
        $s[0] = float_mod($s[0] * 16807, $M);
        $s[1] = float_mod($s[1] * 37 + $s[0], $M);
        $s[2] = float_mod($s[2] + $s[3] + $i, $M);
        $s[3] = float_mod($s[3] * 48271, $M);
        
        my $sum = $s[0] + $s[1] + $s[2] + $s[3];
        my $idx = $sum % 30; # 30 很小，直接用 % 即可

        # JS 取餘數可能是負的 (例如 -1 % 30 = -1)，Perl 則是 ( -1 % 30 = 29 )
        # 這裡 $sum 是四個正數(0~M)相加，理論上不會是負數。
        # 但為了 100% 移植原程式碼的防禦邏輯：
        if ($idx < 0) { $idx += 30; }
        
        $res .= substr($b_str, $idx, 1);
    }

    return $res;
}

# 輔助函式：安全的浮點數取餘數 (Float Modulo)
# 用途：解決 32-bit Perl 環境下，大數 (如 3.6e13) 直接使用 % 運算符會導致整數溢位的 BUG。
# 原理：a % n = a - floor(a / n) * n
sub float_mod {
    my ($val, $mod) = @_;
    # 使用 int() 截斷小數部分，相當於 floor (針對正數)
    # 這裡利用 Perl 的浮點數精度 (Double) 來進行運算，避免強制轉型為 32-bit Int
    my $res = $val - int($val / $mod) * $mod;
    return $res;
}

    -- 使用獨立變數模擬陣列，全部使用 BIGINT
    DECLARE @s0 BIGINT = 19850721;
    DECLARE @s1 BIGINT = 98765432;
    DECLARE @s2 BIGINT = 12345678;
    DECLARE @s3 BIGINT = 55119733;

    ------------------------------------------------------------
    -- 預處理: encodeURI 與 Salt
    ------------------------------------------------------------
    -- 對應 JS: a = encodeURI(a) + b;
    -- 重要提示：SQL 沒有完全等同 JS encodeURI 的內建函式。
    -- 此處假設傳入的 @a 已經是不含特殊字元或已編碼過的字串。
    -- 若您輸入純英數 (Alphanumeric)，邏輯是完全精確的。
    DECLARE @InputString NVARCHAR(MAX) = @a + @b;
    DECLARE @InputLen INT = LEN(@InputString);
    
    DECLARE @i INT = 1; -- SQL 字串索引從 1 開始
    DECLARE @c BIGINT;  -- 儲存字元編碼

    ------------------------------------------------------------
    -- 第一迴圈: 混淆計算
    ------------------------------------------------------------
    WHILE @i <= @InputLen
    BEGIN
        -- 對應 JS: var c = a.charCodeAt(i);
        SET @c = UNICODE(SUBSTRING(@InputString, @i, 1));

        -- 對應 JS: s[0] = (s[0] * 16807 + c) % M;
        SET @s0 = (@s0 * 16807 + @c) % @M;

        -- 對應 JS: s[1] = (s[1] * 48271 + s[0]) % M;
        SET @s1 = (@s1 * 48271 + @s0) % @M;

        -- 對應 JS: s[2] = (s[2] ^ s[0]) % M;
        -- SQL Server 支援 ^ 作為 Bitwise XOR
        SET @s2 = (@s2 ^ @s0) % @M;
        
        -- 對應 JS: if(s[2] < 0) s[2] += M;
        -- 修正負數模運算結果
        IF @s2 < 0 SET @s2 = @s2 + @M;

        -- 對應 JS: s[3] = (s[3] + s[1] + c * 13) % M;
        SET @s3 = (@s3 + @s1 + (@c * 13)) % @M;

        SET @i = @i + 1;
    END

    ------------------------------------------------------------
    -- 第二迴圈: 產生結果字串
    ------------------------------------------------------------
    DECLARE @res VARCHAR(41) = '';
    DECLARE @k INT = 0; -- 對應 JS 第二個迴圈的變數 i (從 0 到 40)
    DECLARE @idx BIGINT;

    WHILE @k < 41
    BEGIN
        -- 對應 JS: s[0] = (s[0] * 16807) % M;
        SET @s0 = (@s0 * 16807) % @M;

        -- 對應 JS: s[1] = (s[1] * 37 + s[0]) % M;
        SET @s1 = (@s1 * 37 + @s0) % @M;

        -- 對應 JS: s[2] = (s[2] + s[3] + i) % M; (此處 i 為迴圈變數 @k)
        SET @s2 = (@s2 + @s3 + @k) % @M;

        -- 對應 JS: s[3] = (s[3] * 48271) % M;
        SET @s3 = (@s3 * 48271) % @M;
        
        -- 對應 JS: var idx = (s[0] + s[1] + s[2] + s[3]) % 30;
        SET @idx = (@s0 + @s1 + @s2 + @s3) % 30;

        -- 對應 JS: if (idx < 0) idx += 30;
        IF @idx < 0 SET @idx = @idx + 30;

        -- 對應 JS: res += b.charAt(idx);
        -- SQL SUBSTRING 是 1-based，所以是 @idx + 1
        SET @res = @res + SUBSTRING(@b, @idx + 1, 1);

        SET @k = @k + 1;
    END

    RETURN @res;
END

        s[2] = (s[2] ^ s[0]) % M;

總結來說，這是一個為了「生存」而設計的演算法。它不追求最快的速度，也不依賴最新的標準，但它能在任何你想像得到或想像不到的艱困運算環境中，穩定地為你提供一道獨特且難以預測的安全指紋。
