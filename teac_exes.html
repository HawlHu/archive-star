跨平台恆定記憶體海綿結構之自訂加密標準(EXES)實作與防篡改拓撲分析

<<Implementation of EXES: A Cross-Platform Constant-Memory Sponge Construction Encryption Standard and Anti-Tampering Topology Analysis >>

摘要 (Abstract)

隨著資訊系統迭代，維持老舊架構（如 VB6、PHP 4）與現代前端（HTML5/JS）間的安全通訊成為企業資安的重大挑戰。本研究針對「EXES (EXtended Encryption Standard) V5.8」加密系統進行深度剖析。該系統基於 ChaCha20 核心置換演算法，結合雙海綿架構 (Dual-Sponge AEAD) 與創新的 Base62 拓撲乘數轉換。實驗結果顯示，在高達 50 萬次的工業級極限壓力測試下，系統展現出恆定記憶體 (O(1)) 的穩定性、香農熵值高達 7.9996 bits/byte，並能 100% 攔截密文竄改與邊界溢位攻擊，為跨時代平台的資料加密提供了一套高強度且完美同步的解決方案。

 

關鍵字 (Keywords)

EXES 加密標準、ChaCha20、海綿函數 (Sponge Construction)、認證加密 (AEAD)、Base62 拓撲、恆定記憶體

 

英文摘要 (English Abstract)

Maintaining secure communication between legacy architectures (such as VB6, PHP 4) and modern front-ends remains a critical challenge in enterprise cybersecurity. This study conducts an in-depth analysis of the "EXES V5.8" encryption system. Based on the ChaCha20 core permutation, it integrates a Dual-Sponge AEAD architecture and an innovative Base62 topology multiplier. Experimental results under industrial-grade stress testing (up to 500,000 iterations) demonstrate constant-memory O(1) stability, a Shannon entropy of 7.9996 bits/byte, and 100% immunity against ciphertext tampering and boundary overflow attacks. EXES provides a highly secure, perfectly synchronized solution for cross-platform data encryption.

 

一、 背景 (Background)

在當今金融機構、傳統製造業及企業內網中，仍大量運行著十幾年前的遺留系統（Legacy Systems）。這些系統（如基於 Visual Basic 6 或早期 PHP 版本構建的後端）往往缺乏對現代密碼學套件（如 AES-GCM 或 Libsodium）的原生支援。當這些系統需要與現代 Web 瀏覽器進行安全的資料交換時，強行移植現代加密套件常會遭遇 32 位元整數溢位、編碼失真或記憶體洩漏等嚴重問題。

 

二、 動機 (Motivation)

為了解決跨平台加密演算法在不同直譯器與編譯器中運算結果不一致的痛點，業界需要一套無外部依賴、純基於底層數學與位元運算，且具備現代 AEAD 認證加密防禦級別的標準。EXES (EXtended Encryption Standard) 正是為此環境而生的自訂加密協議，本研究旨在探討其架構之可靠性及抵禦常見密碼學攻擊的能力。

 

三、 目的 (Purpose)

本研究的主要目的包含：

  • 分析 EXES V5.8 中 ChaCha20 海綿架構的數學原理與領域隔離 (Domain Separation) 機制。
  • 驗證 Base62 拓撲乘數 (Topology Multiplier) 在防篡改與資料完整性驗證上的實效。
  • 透過建構工業級自動化測試沙盒，評估演算法的記憶體消耗、效能瓶頸及抗溢位能力。

 

四、 研究方法 (Methodology)

本研究採用靜態程式碼審查與動態壓力測試雙管齊下的方法：

  • 架構解構：解析 JS、PHP、VB6 三種語言之原始碼，探討其如何克服 32 位元溢位（如 VB6 使用 Currency 型態模擬）及 AST 解析限制（如 PHP 的極度扁平化編碼）。
  • 環境建構：利用 HTML5 搭配 Web Worker 建置非同步壓力測試儀表板 (utility_exes.html)。
  • 壓力參數：設定測試乘數為 500,000x，執行包含 Null Byte 注入、Zalgo 溢位字元、並發競爭條件 (Race Condition)、金鑰雪崩效應 (Key SAC) 等高達 70 項以上的極端邊界測試。

 

五、 研究結果 (Results)

經過完整的自動化滲透與統計分析，取得以下數據與結果：

  • 邊界滲透防禦：在密文竄改 (Body/Header)、Null 字節注入、Zalgo 溢位等測試中，異常放行次數為 0，記憶體崩潰次數為 0。
  • 亂數分佈與熵值：總體香農熵值 (Shannon Entropy) 達到 7.9996 bits/byte，接近理論極限的 8.0。
  • 雪崩效應：明文雪崩效應 (PT SAC) 約為 50.30%，金鑰雪崩效應 (Key SAC) 約為 49.79%，精準落在密碼學理想基準值 (50%) 區間。
  • 記憶體管理：串流分析演算法在 50 萬次循環中保持 O(1) 的記憶體消耗，無發生 OOM (Out of Memory) 現象。

 

六、 研究發現 (Findings)

本研究有幾項關鍵發現：

  1. 拓撲乘數具備前置濾波效應： 傳統 Base64 在解碼時若遇惡意竄改，通常需計算至最後的 MAC 驗證才會拋出錯誤。EXES 的拓撲乘數 (`val * 54 + modMix`) 將資料膨脹，解碼時若 `(expandedVal % 54) !== (val % 54)` 則直接判定非法，大幅降低了遭受攻擊時的 CPU 運算開銷。
  2. 雙領域隔離的可靠性： 利用 `0x44` 與 `0x55` 分離加密狀態與 MAC 狀態，徹底杜絕了流密碼 (Stream Cipher) 常見的金鑰重用或位元反轉攻擊 (Bit-Flipping Attack)。
  3. 跨語言降級工程的必要性： VB6 中的 `Currency` 型別實作與 PHP 中避免巢狀 AST 的手法，證明了只要掌握底層位元原理，即使在資源與語法受限的環境下，也能實現極高規格的資安防禦。

 

七、 未來可延伸研究 (Future Work)

雖然 EXES 在傳統運算環境下展現出卓越的安全表現，未來仍可針對以下方向進行擴展：

  • 後量子密碼學 (PQC) 的融合：探討如何將抗量子計算的密鑰封裝機制 (KEM) 引入 EXES 的海綿初始化階段。
  • WebAssembly (WASM) 效能最佳化：在不破壞相容性的前提下，將 JS 版本的位元運算重寫為 WASM 模組，進一步提升前端在處理 MB 級距距大檔的加解密吞吐量。
